# Розбір конфлікту: `.editorconfig`

Відповідальна: @tyshchenkooleksandra-hue

Кожна з нас **незалежно** написала свій `.editorconfig`. PR #2 злився першим, PR #3 отримав
конфлікт `add/add`: обидві гілки створили той самий файл з різним вмістом.

## Що конфліктувало

```text
[*]
indent_style = space
<<<<<<< HEAD                      ← моя версія (PR #3)
indent_size = 4

[*.{yml,yaml,json}]
indent_size = 2

[*.sh]
indent_size = 4
=======
indent_size = 2                   ← версія з main (PR #2)

[*.py]
indent_size = 4
max_line_length = 100

[*.sh]
indent_size = 2

[*.go]
indent_style = tab
>>>>>>> origin/main
```

Розійшлися базовий відступ (`4` / `2`), відступ для bash (`4` / `2`), а в моїй версії не було
секцій для Python, Go і `.bat`.

## Помилкове вирішення: «Accept Both Changes»

Найшвидша кнопка в редакторі — залишити обидві половини. Файл виходить **синтаксично коректним**,
жоден парсер не скаржиться:

```ini
[*]
indent_style = space
indent_size = 4               ; з моєї половини

[*.{yml,yaml,json}]
indent_size = 2

[*.sh]
indent_size = 4
indent_size = 2               ; ← цей рядок належав секції [*], а тепер опинився в [*.sh]

[*.py]
...
```

Рядок `indent_size = 2` із половини `main` стояв одразу після `indent_style` у секції `[*]`.
Після склеювання він опинився **нижче заголовка `[*.sh]`** — і змінив зміст: тепер це другий
`indent_size` для bash (діє останній), а `[*]` залишився з `4`.

Що фактично отримує редактор (вивід `editorconfig`, бібліотеки, якою користуються плагіни):

| Файл | Помилкове вирішення | Узгоджене значення | Наслідок |
|---|---|---|---|
| `build.bat` | `indent_size: 4` | `2` | усі файли без власної секції змінили відступ |
| `main.go` | `indent_size: 4` (табом) | `2` | ширина таба в Go-файлах інша |
| `README.md`, `.toml`, `.ini`… | `indent_size: 4` | `2` | так само |
| `run.sh` | `indent_size: 2` | `2` | випадково збіглося — і тому помилку важко помітити |

Ще гірший варіант — «Accept Current» (узяти лише свою версію): файл теж валідний, але зникають
ключі, яких у мене не було, і бат-файли тихо переходять на `LF`:

| Файл | «Accept Current» | Узгоджене значення |
|---|---|---|
| `main.go` | `indent_style: space` | `tab` — `gofmt` переформатує кожен файл |
| `build.bat` | `end_of_line: lf` | `crlf` — `cmd.exe` ламає мітки й `goto` |
| `tool.py` | немає `max_line_length` | `100` |

## Правильне вирішення

Взяти версію, **узгоджену й задокументовану** в [`docs/editor-config.md`](editor-config.md):
`indent_size = 2` для `[*]` і bash, `4` для Python, таби для Go й Makefile, `CRLF` для `.bat`.

Чому саме так:

1. **Конфлікт вирішується рішенням команди, а не вибором «моє/твоє».** Для кожного значення в
   `docs/editor-config.md` є обґрунтування (PEP 8, Google Shell Style Guide, вимога `make`). Моя
   версія таких обґрунтувань не мала — `4` для bash було звичкою, а не рішенням.
2. **Конфіг і документація не мають розходитися.** Будь-яке з помилкових вирішень робить
   `docs/editor-config.md` неправдою, хоча сам файл виглядає нормально.
3. **Перевіряти результат, а не текст.** Після вирішення конфлікту в структурованому файлі
   дивитися треба на фактичну поведінку:

   ```bash
   npx editorconfig run.sh tool.py main.go build.bat
   ```
4. **Не загубити корисне з другої половини.** З моєї версії збережено секцію
   `[*.{yml,yaml,json}]`: зараз вона збігається з `[*]`, але фіксує відступ YAML незалежно від
   базового. Без неї зміна `[*]` на `4` мовчки змінила б структуру всіх workflow
   (знайдено на рецензії PR #3).

## Висновок

Конфлікт у тексті видно очима: речення обривається або повторюється. Конфлікт у конфігурації
небезпечніший — файл після склеювання залишається валідним, а система поводиться інакше, і
помилка проявляється пізніше, в іншому файлі, в іншої людини.

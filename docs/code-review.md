# Чек-лист рецензування pull request

Відповідальна: @AlexandraTyshchenko

Чек-лист під **консольні утиліти** курсу. Кожен пункт сформульовано так, щоб на нього можна було
відповісти «так» або «ні» без суперечок. Якщо відповідь «ні» — це і є зауваження в рецензії.

**Чого тут немає навмисно:** «код якісний», «читається добре», «помилки оброблено нормально».
На такі пункти кожен відповідає по-своєму; їх замінено на конкретні перевірки.
Коми, пробіли й відступи — робота форматера й `.editorconfig`, не рецензента.

## 1. Pull request

- [ ] Заголовок PR відповідає формату Conventional Commits (`feat:`, `fix:`, `docs:`…)
- [ ] PR змінює одну річ: усі файли в diff стосуються теми із заголовка
- [ ] У розділі «Як перевірити» є команда, яку можна скопіювати й виконати

## 2. Запуск

- [ ] Утиліта запускається командою з README без додаткових кроків
- [ ] `--help` виводить усі параметри, описані в README, і жодного зайвого
- [ ] Запуск без обов'язкових аргументів завершується з ненульовим кодом і підказкою використання

## 3. Коди виходу й потоки

- [ ] Успішне виконання повертає `0`
- [ ] Кожна помилка повертає ненульовий код, і цей код описаний у README
- [ ] Повідомлення про помилки йдуть у `stderr`, а результат — у `stdout`
- [ ] Жодна очікувана помилка (немає файла, немає мережі, неправильний аргумент) не завершується трасуванням стеку / `Traceback`
- [ ] Повідомлення про помилку називає, що саме не так: шлях файла, ім'я параметра, отримане значення

## 4. Вхідні дані

- [ ] Неіснуючий файл, порожній файл і файл без прав на читання дають різні зрозумілі повідомлення
- [ ] Шлях із пробілами й кирилицею обробляється коректно
- [ ] Порожній вхід (`< /dev/null`) не зависає й не падає

## 4а. Код

- [ ] Лінтер і форматер проходять без помилок (команда з README)
- [ ] Немає закоментованого коду й налагоджувальних `print`/`echo`

## 5. Безпека

- [ ] У diff немає паролів, токенів, ключів і файлів `.env`
- [ ] Значення з аргументів не підставляються в shell-команду без лапок

## 6. Документація

- [ ] README оновлено, якщо змінилися параметри, коди виходу чи формат виводу
- [ ] Приклад виводу в README збігається з реальним виводом поточної версії
